# FAT32

`fat` is a Ring 3 server that reads a FAT32 volume of the disk and answers the same protocol as `ramfs` (see [file system](filesystem.md)), so a client reaches it through the `vfs` as `/fat/...` with the same client library. It talks to the disk through the block protocol of [block storage](../../drivers/block_storage.md), as any other client of `ata`, and has no capability of its own. It reads and writes (see [Writing](#writing)).

## Mounting
`fat` waits for the message `rs` sends it, whose first argument is the block device to serve: the manifest line is `fat path=servers/fat arg=2` (device 0 is the whole disk, the partitions follow). It connects to `ata`, reads the first sector of that device and parses it as a FAT32 boot sector. If the device does not exist or is not FAT32 it prints `fat: device N is not a FAT32 volume` and exits. A line without `arg=` leaves the server waiting for it.

The boot sector (`shared/include/cock/abi/fat32.hpp`, `parseBpb`, covered by the host tests) is accepted when:
- the signature `0x55 0xAA` is at byte 510 and a sector is 512 bytes (other sector sizes are refused);
- the sectors per cluster are a power of two up to 128, there are 1 to 4 FATs and at least one reserved sector;
- the root entry count and the 16-bit FAT size are zero and the 32-bit FAT size is not (the usual sign of FAT32), and the version is 0;
- the total sector count fits in the partition, the reserved sectors and the FATs leave room for data, and the cluster count is between 65525 and `0x0FFFFFF4` (a smaller count is FAT12 or FAT16 whatever the label says);
- the FAT is big enough for that many clusters and the root cluster is a data cluster.

Only the first FAT is read. The FSInfo sector (its address is in the boot sector) is read when its three signatures are right: the free cluster count, when it is not the "unknown" value, and the next free hint are kept in memory and written back after each operation that allocates or frees clusters. A volume on the whole-disk device (device 0) is served read only, because `ata` refuses writes to it.

## What it serves
- **Paths.** `/`, `a/b` and `/a/b/` are the same; a component is looked up in its directory with the case ignored, against the long name when the entry has one and the short name otherwise. `.` and `..` are not listed and not followed by name.
- **Names.** Long file names (up to 255 UTF-16 units) are assembled from their entries and used only if the sequence is complete and its checksum matches the short name; otherwise the short name is shown. They are turned into UTF-8 (surrogate pairs become one four-byte character, a lone surrogate becomes `?`), so a client opens `/fat/café.txt` by its UTF-8 name. Matching ignores the case of ASCII letters only; other characters must match byte for byte. Short names use the lower-case flags of the entry (`hello.txt`) and their bytes beyond ASCII are passed as they are.
- **Files.** `FS_READ` follows the cluster chain from the cluster of the file. Each open handle remembers the last cluster it reached, so a sequential read does not walk the chain again. A read that starts on a sector and covers whole sectors inside a cluster goes to the disk in one request, straight into the window, up to the 8 sectors a window holds; the rest goes through a one sector buffer.
- **Directories.** `FS_READDIR` lists the entries in disk order (deleted entries, the volume label and the dot entries are skipped), `OUT_OF_RANGE` after the last one. A directory that cannot be read to the end also answers `OUT_OF_RANGE`.
- **Sessions and handles** are as in `ramfs`: 8 clients, 16 handles each, windows released for dead clients.

## Writing
- **Operations.** Create, write at or before the end of the file, truncate (open with `TRUNCATE`), delete, make and remove directories, and rename or move a file or a directory.
- **Names.** A name that is a valid 8.3 name (up to 8 characters, a dot and up to 3, from letters, digits and ``$%'-_@~`!(){}^#&``, each part all upper case or all lower case) is stored as the short entry alone, with the lower-case flags (`note.txt` stays as typed). Any other name gets a **long file name**: its UTF-8 is decoded and written as UTF-16 in as many long entries as needed (13 characters each, last part first, with the checksum of the short name), followed by the short entry. The short name is the upper-case name when it fits 8.3 (`Hello.txt` becomes `HELLO.TXT`) and otherwise an alias of the form `LONGNA~1.TXT`: spaces and dots dropped, characters that are not allowed turned into `_` (one per UTF-8 character), six letters of the base and a tail that grows until no entry of the directory has that alias. A name with a control character, one of `\ / : * ? " < > |`, an invalid UTF-8 sequence, more than 255 UTF-16 units, or a trailing dot or space answers `BAD_REQUEST`. The slots of the entries are found as a run of free ones (deleted or past the end), growing the directory when the run does not fit. Deleting a file removes its long entries too.
- **FAT updates.** Every change to the FAT goes to all the copies. A new cluster is marked end of chain before it is linked, a deleted file loses its directory entry before its chain is freed, a truncated file gets its entry updated before the chain is freed, so a crash leaves lost clusters that `fsck` reclaims, never an entry that points at free space. The search for a free cluster starts at the hint and wraps around.
- **Data.** A write that starts on a sector and covers whole sectors goes to the disk in one request (up to 8 sectors); the rest is read, patched and written through a one sector buffer, and a sector that lies wholly past the old end of the file starts from zeros, so no old data of a deleted file ends up in a new one.
- **Directories.** `mkdir` takes a cluster, clears it, writes the `.` and `..` entries (`..` is cluster 0 when the parent is the root, as the format requires) and then the entry in the parent; `rmdir` needs a directory with nothing but those two entries and frees its chain after deleting its entry. `rename` writes the new entry (a copy of the old one with the new name and its long entries) before it deletes the old one, and a directory moved to another parent gets its `..` rewritten; a move into itself is refused, and a crash between the two writes leaves two names for one chain, which `fsck` reports. A directory grows by a cleared cluster when no run of free entries is long enough. A `rename` onto an existing name replaces it when both are files, or both are directories and the target is empty (`NOT_EMPTY` otherwise); a file onto a directory or the reverse answers `EXISTS`, and a target that a client has open answers `BUSY`. The target is deleted before the new entry is written. A rename that only changes the case of a name deletes the old entries and writes the new ones in that order, because both names map to the same short entry.
- **Dates.** New entries get the creation, access and write date and time of the CMOS clock, asked from the `rtc` server (`userland/lib/include/cock/user/clock.hpp`; the server reads twice until two reads agree, BCD or binary, 12 or 24 hours; the conversion is `shared/include/cock/abi/datetime.hpp`); a write, truncate or rename updates the write time. FAT keeps 2 second steps and the volume has no time zone, so the clock is taken as UTC. If `rtc` is not there or does not answer, the server writes 1980-01-01. `fat` holds no port capability for the clock.
- **Clean flag.** Every operation that writes clears the "clean shutdown" bit of the second FAT entry (on all copies) first and sets it again when it ends, so the volume is clean whenever the server is idle. A volume that is mounted with the bit clear (a crash in the middle, or a volume that was not unmounted) is mounted read only until `fsck` repairs it.
- **Not done.** There are no hidden or read-only attributes, and the creation time is not kept apart from the write time on a rename.

## Hostile images
The server never trusts the disk. Every cluster number read from the FAT or from a directory entry must be a data cluster of the volume before it is followed; a chain that ends early or points outside makes the read fail with `IO_ERROR`; a directory walk stops after as many clusters as the volume has, so a loop in a chain ends; the offset and length of a read are clamped to the size in the entry, so a size larger than the chain gives `IO_ERROR`, not a read past the data.

## Limits
512 byte sectors; one volume; case-insensitive matching for ASCII only; file sizes up to 4 GiB - 1.

## Tests
- Host tests (`test/host/test_fat32.cpp`): the boot sector (a good one and ten refusals), FAT entries and end of chain, short names with case flags and the kanji escape, skipped entries, long names with a wrong checksum and with a missing part, and the UTF-8 conversion of two, three and four byte characters, a lone high surrogate and a lone low surrogate.
- End to end: `scripts/make_test_disk.sh` puts these files in the FAT32 partition: `HELLO.TXT` (`hello from fat`), the same text under the long name `A long file name.txt`, `SUBDIR/NESTED.TXT`, and `BIG.BIN` with 20000 bytes of the letters `A` to `Z` repeating (many clusters, because the test volume uses one sector per cluster). `fatclient` reads each through `/fat/...` with other capitalization where it matters, reads the big file in windows and checks every byte, reads across a sector boundary, reads a file whose long name has non-ASCII characters (`café ñ.txt`), lists `/fat` (six entries with `SCRATCH`, with the right types), checks that a missing file and a path through a file are refused, and checks that `/hello.txt` of the initrd still reads. The test requires `fat: device 2,`, `vfs: 2 mounts`, `fatclient: hello says hello from fat` and `fatclient: ok`, with an MBR disk and with `DISK_SCHEME=gpt`.
- Writing: host tests for the 8.3 name encoder (case flags and refusals), the name plans (short, cased, lossy), the aliases (tails, UTF-8, dots), the UTF-8 decoder and its refusals, long entries read back by the parser (one, two and twenty entries, four-byte characters), the entry encoder, timestamps, FAT updates that keep the top four bits, FSInfo and the new boot sector fields. End to end, `scripts/make_test_disk.sh` adds a `SCRATCH` directory and `fatclient` runs the write check in it (see [file system](filesystem.md#tests)); `scripts/qemu_userland_test.sh` then extracts the partition, requires `fsck.fat -n` to pass and reads `SCRATCH/keep.txt` back with `mtype`. CI installs `dosfstools` for this.
- The probe checks of the file server now run through the `vfs`, so the refusals (bad handle, bad path, bad flags, reads past the end) are also checks of the proxy.
