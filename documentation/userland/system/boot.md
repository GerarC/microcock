# How the system starts the userland

1. The Makefile builds every `userland/*/*/Makefile` into `build/userland/<name>.elf`. With `TEST_INITRD=1` it also builds `test/userland/*/Makefile`.
2. It packs the files of the `initrd/` folder and every program of those folders that is not a boot module (under `drivers/` and `servers/` those of `userland/drivers/` and `userland/servers/`, under `bin/` the applications and the test programs, each without the `.elf` suffix) into `build/initrd.tar` (ustar). With `TEST_INITRD=1` the files of `test/initrd/` are added, and the `manifest.conf` and `mounts.conf` of the two folders are joined (system lines first), so a normal `make iso` boots the system with no test program and `make iso TEST_INITRD=1` boots the same system plus the tests. It writes a `grub.cfg` with one `module` line for each program of `USERLAND_BOOT_ORDER` (`rs`, `names`, `ramfs`, `vga_driver`), and a last line for the archive, named `initrd`. The archive is a data module (see [boot modules](../../core/memory/boot_modules.md)), so it never becomes a process.
3. The kernel loads each module as a process (`rs`, `names`, `ramfs`, `vga_driver`) and gives the root capabilities to the first one, `rs`. `rs` creates the process manager `pm` itself and every other program through it; `init` starts the programs marked `parent=init` (see [pm](../servers/pm.md)).
4. `rs` labels `names` and gives it the right to pass on `IPC` capabilities, registers `ramfs`, grants `ramfs` the `initrd` and sends it `CAPABILITY_GRANTED`; this is the only policy written in its code. It then reads `manifest.conf` through `ramfs`, parses it, sends the programs and the `ipc=` policy to the name server, and runs each line in order (see [manifest](manifest.md)). A spawned process is born with no capabilities, so the grants of its line are what it gets. `vga_driver` maps the screen, and `kbd` enables the port and binds the interrupt.
5. A key press travels: keyboard controller, IRQ 1, kernel (`IRQ_NOTIFICATION`), `kbd` reads the scan code and acknowledges the line, `kbd` sends `CONSOLE_KEY` to `tty`, `tty` edits the line and asks `console` for the echo, and `console` sends it to `vga_driver`, which draws it.

A driver that needs a new capability needs a new `cap_grant` in `userland/servers/rs/src/main.cpp`; see [capabilities](../../core/capabilities.md). The display server is described in [VGA](../drivers/vga.md) and the keyboard driver in [keyboard](../drivers/keyboard.md).
