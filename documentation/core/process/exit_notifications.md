# Exit notifications

`SYS_PROC_CREATE` takes a flags argument (see [spawn](spawn.md)); `SPAWN_NOTIFY_EXIT` asks the kernel to tell the creator when the new process ends. The process keeps its parent id, the flag and an exit status. When its last thread ends, `TaskManager::notifyThreadDeath` stores the notice in the record of the parent process (`IPC::notifyExit`), and the main thread of the parent receives it as a `PROCESS_EXITED` message from `KERNEL_SENDER` (`arg0` the process id, `arg1` the status), before any message of the inbox. The record is not the inbox, so a full inbox cannot lose it. It never overflows: `SYS_PROC_START` of a process created with the flag reserves one of the `MAX_NOTIFIED_CHILDREN` (16) slots of the creator and fails when none is free; the slot is given back when the parent reads the notice. A spawner that does not read therefore stops being able to start more notified children, instead of losing a notice. Only the main thread of the parent reads notices; if the parent process ends first, its record goes with it. `SYS_PROC_ALIVE` remains a check that needs no notice. `rs` asks for it for the programs the manifest repeats (`repeat=`) and waits for the notice with a receive timeout; it prints `rs: <name> exit notices N/M` when the run is over. Restarting a server that died is not done yet: the notice gives `rs` what it needs, the policy is still to be written.
