# exec

`SYS_PROC_EXEC` is the kernel part of `exec`, done as in Minix 3: the program asks `pm`, `pm` builds the new image as a pending process (see [spawn](spawn.md)), and the kernel swaps it in. The caller needs the `SPAWN` capability, owns the pending process, and the target must be the main thread of another user process that waits for the reply of a call the caller is serving (accepted, or detached with `ipc_defer`). That is the consent of the target, and since it is blocked its address space is not the active one. Everything that can fail happens first (handle, entry point mapped, stack of the new image mapped), so a failure leaves the old image running.

After that point: the other threads of the target end (`Scheduler::terminateThread`: out of the ready queue, the futex and timer lists and the lists of the server they called, calls they served fail, then the usual death path), `Process::swapImage` exchanges the address space, region table, page quota and name with the pending process, the shared memory the target held and the pending processes it owned are dropped, `Thread::restartAt` closes its call with no reply, drops its inbox and rebuilds its context at the new entry on the new stack, and the pending process, which now holds the old image, is deleted. The process id, parent, capabilities, service label, endpoints and exit notices stay. The new image gets `initial` in `EAX`; `pm` makes it the address of the argument page (`abi::exec`), which carries the arguments and the initial handle of the old image, so the new program can still reach the name server.

Only the main thread may ask for `exec` of its process: the id of a process is the id of its main thread, which is the thread that restarts. The ELF loader that remains in the kernel (`cock/core/loader`, see [ELF loader](../elf_loader.md)) serves only the Multiboot boot modules (`rs`, `names`, `ramfs`, `vga_driver`), which no user loader can start because nothing runs before them.
