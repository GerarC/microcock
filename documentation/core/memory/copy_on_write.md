# Copy on write

`fork` copies a process without copying its memory. The kernel part is one primitive, `SYS_PROC_FORK` (see [fork](../process/fork.md)), which asks the [VMM](vmm.md) for `cloneAddressSpace` of the parent. It lives in the kernel because only the kernel writes page tables; the policy (who may fork, the table of processes) is in `pm`.

* **The copy.** `Paging::cloneAddressSpace` allocates a new directory, which shares the kernel half as in `createAddressSpace`, and a page table for every user page table of the source. For each present entry of a page the source owns it adds a reference to the frame (`shareFrame`, see [PMM](pmm.md#reference-counts)); if the page was writable it clears `WRITEABLE` and sets `COPY_ON_WRITE` in **both** tables. Read only pages (the code of the program) stay as they are, shared for good. Pages marked `NOT_OWNED` (shared memory and devices) are copied as they are and stay shared and writable, which is what a shared mapping means. Only the directory and the tables take frames now; the source must not run, so its stale TLB entries die with the next switch to it. The copy uses temporary slots of the kernel (`0xE0000000` and up, see [address map](address_map.md)) to edit the two address spaces, and it stops when the free frames would fall under the reserve the kernel keeps (`KERNEL_RESERVED_FRAMES`). A failure destroys the copy, which returns every table and every reference it took; the source may keep entries marked copy on write, which resolve by themselves.
* **The first write.** It raises a page fault (present, write, from Ring 3). `core::events::on_exception` asks `VirtualMemoryManager::resolveCopyOnWrite` before it logs anything (see [exceptions](../../arch/interrupts/exceptions.md)). When the frame has other references, a new frame takes a copy of the page, replaces the old one in the table with `WRITEABLE` and without `COPY_ON_WRITE`, and the old frame loses a reference; when this mapping is the last one, the entry just becomes writable. The instruction then runs again. A write to a page that is read only for any other reason, or an address that is not mapped, is not copy on write and still kills the thread as before.
* **Writes by the kernel.** The kernel writes to a user buffer only after `isUserRangeValid(..., write = true)`, which resolves the copy on write pages of the range. `mapPagesAt` does the same before it merges write permission into a page that is already mapped.
* **No frame at the write.** The copy takes a frame from the allocator without the kernel reserve. If none is free, `resolveCopyOnWrite` fails and the thread is killed by the fault, as when an address is not mapped; a system call that needs a copy returns its failure. `fork` does not reserve the frames for the copies (the same bet as Linux): it only checks that the tables fit.
* **Limit.** A frame can have 255 references. A `fork` that would pass it fails and leaves nothing behind.
