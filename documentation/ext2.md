# ext2

`ext` is a Ring 3 server that reads an ext2 volume of the disk and answers the same protocol as `ramfs` and `fat` (see [file system](filesystem.md)), so a client reaches it through the `vfs` as `/ext/...` with the same client library. It talks to the disk through the block protocol of [block storage](block_storage.md) and has no capability of its own. It reads and, on a suitable volume, writes (see [Writing](#writing)).

## Mounting
`ext` waits for the message `init` sends it, whose second argument is the block device to serve: `ext path=bin/ext.elf arg=3`. It connects to `ata`, reads the superblock (bytes 1024 to 2047 of the device), checks it (`shared/include/cock/abi/ext2.hpp`, `parseSuperblock`, covered by the host tests) and loads the root inode. On any failure it prints why and exits. The server shares `userland/lib/include/cock/user/file_server.hpp` with `fat`: sessions, handles, windows and the request loop are the same, and each server only says how to resolve a path, read bytes and list a directory.

The superblock is accepted when:
- the magic is `0xEF53`, the block size is 1024, 2048 or 4096 bytes, and the first data block is 1 for 1024 byte blocks and 0 otherwise;
- the inode size is a power of two from 128 to 512 (revision 0 volumes always use 128);
- the blocks per group and inodes per group are not zero and fit one bitmap block, the volume fits in the device, and there are enough groups for the inode count;
- **the incompatible feature set contains nothing but `filetype`.** Anything else makes the server refuse the volume and print one line per feature, for example `ext: device 4: unsupported feature extents`. That is how an ext4 volume is refused (extents, flex_bg, 64bit, ...), how a volume with a journal waiting to be replayed is refused (`needs_recovery`), and how compression, encryption, inline data, meta block groups and the rest are refused. The names are in a table in the header; an unknown bit prints as `unknown`.
- The compatible and read-only-compatible sets are not checked for reading: neither can change how a volume is read. A clean ext3 volume (journal present, no recovery needed) therefore mounts, and is read as ext2. They decide whether the volume may be written: see below.

A volume whose inode has the extents flag or the inline data flag is refused file by file, in case the feature word and the inodes disagree.

## What it serves
- **Paths.** Components are matched byte for byte. `.` and `..` exist in every directory and can be used in a path; `..` of the root is the root. They are not listed.
- **Files.** The block map is the classic one: 12 direct blocks and single, double and triple indirect blocks (`blockPath` in the header turns a file block number into the slots to follow, and the host tests walk every boundary). A block pointer of 0 is a hole and reads as zeros, so sparse files work. Every block number read from the disk must lie inside the volume before it is followed. Sizes of 2 GiB or more are cut to 2 GiB - 1. A read that starts on a sector boundary goes to the disk in one request for as many whole sectors as one block and one window allow; the rest goes through a one sector buffer.
- **Directories.** Entries are walked block by block; a block with a damaged record (bad length, name longer than its record) is skipped from the damage on. Entries of types other than files, directories and symbolic links (devices, pipes, sockets) are not listed and cannot be opened. Hashed directories (`dir_index`) are read as plain lists, which every ext2 directory is.
- **Symbolic links.** A path is resolved through them: a fast link (target shorter than 60 bytes, kept in the inode) and a slow one (target in a data block, up to 255 bytes) are followed at any component, including the last, up to 8 links per path (a loop makes the open fail). A relative target starts at the directory that holds the link; an absolute one starts at the root **of this volume**, because the root of the machine is not known to the server. A link is listed with the type `SYMLINK` and opens as its target.
- **Sessions and handles** are as in `ramfs`: 8 clients, 16 handles each.

## Writing
A volume is **writable** when its read-only-compatible features are only `sparse_super` and `large_file`, it has no journal (`has_journal`), its state says it was cleanly unmounted (`VALID`, no `ERROR`), and it is not the whole-disk device. Anything else is mounted read only and the server prints `ext: device N is mounted read only`; writes then answer `READ_ONLY`.

- **Operations.** Create a regular file, write at or before the end, truncate, delete, make and remove directories, and rename or move a file, a link or a directory. No links are made. A file name is any byte string of up to 255 bytes without `/`.
- **Allocation.** Blocks and inodes come from the bitmaps of the group of the inode first and then the following groups; each allocation sets the bit, updates the free counts of the group descriptor and of the superblock, and goes to the disk at once (write through, one sector at a time). A new data block that the write does not cover entirely is cleared first, and indirect blocks are always cleared, so a hole or a new tail never shows old data. The block map is extended through the single, double and triple indirect levels, and `i_blocks` counts every block including the indirect ones.
- **Directories.** A new name goes in the first record with enough slack (a record is split) or in a record of an unused inode; if the blocks are full the directory grows by one block. Deleting merges the record into the one before it, or clears its inode when it is the first of the block. `mkdir` takes an inode and one cleared block holding `.` and `..`, adds the entry (type 2) and counts the new link in the parent and the used directories of the group; `rmdir` needs a directory with only those two entries, removes the entry, frees the block and the inode and takes the counts back. `rename` adds the new entry before it removes the old one; a directory moved to another parent gets its `..` rewritten and the link counts of both parents adjusted, and a move into a directory below itself is refused (the server walks the `..` chain of the target up to the root). An existing target is never replaced.
- **Order.** A new file gets its inode written before the entry, a deleted file loses its entry before its inode and blocks are freed, and a truncate writes the empty inode before the blocks are freed; a crash leaves unreferenced blocks or inodes for `fsck`, never a name that points at free space.
- **Clean flag.** Every operation clears `VALID` in the superblock first and sets it again, with the new free counts, when it ends, so the volume is clean whenever the server is idle. A crash in the middle leaves it unclean, and the next mount is read only until `e2fsck` repairs it.
- **Times.** A new inode gets the access, change and modification time of the CMOS clock, every later change to the inode updates the change and modification time, and a deleted inode gets the deletion time (a zero one is an `e2fsck` error, and a small one is read as the next link of the orphan list, so the server never writes a value below the number of inodes). The manifest line of `ext` carries `io:0x70+2` for the clock; without it every time is the fixed mark 1000000000. The clock is taken as UTC.
- **Not done.** The superblock write time is not touched, backup superblocks and group descriptors are not updated (as with the kernel driver, `e2fsck` rebuilds them), reserved blocks are not kept for root, files of 2 GiB or more are never written, a handle on a directory keeps the size it had when it was opened.

## Limits
512 byte sectors on the device; block sizes up to 4096; inodes up to 512 bytes; no extents; file sizes below 2 GiB; no extended attributes or ACLs; the owner, mode and times are not returned (the protocol does not carry them).

## Tests
- Host tests (`host_test/test_ext2.cpp`): a good superblock (1024 and 4096 byte blocks, revision 0), the refusals (magic, block size, features with their names, `needs_recovery`, unknown bits, inode sizes, geometry), the inode types and the size cut, directory records (a good pair, bad length, bad alignment, a record past the block, a name past its record, the 16 bit name length without `filetype`) and `blockPath` at every boundary up to the last block of the triple level.
- End to end: `scripts/make_test_disk.sh` builds the third partition with `mke2fs -t ext2 -b 1024 -d <folder>` (e2fsprogs 1.43 or later, no root) and the fourth with `mke2fs -t ext4`. The folder holds a small file, `subdir/inner.txt`, `large.bin` (300000 bytes of the letters `A` to `Z` repeating, so it reaches the double indirect level), `sparse.bin` (50000 bytes with `head` at the start and `tail` at the end), an empty file, `many/` with 120 files (a directory of two blocks), a fast link, a slow link whose target has 71 bytes, an absolute link, a relative link into `subdir` and two links that point at each other. `e2fsck -fn` finds both images clean.
- `extclient` reads each through `/ext/...`: the small and nested files, every byte of the large file and reads that cross the end of the direct blocks and the start of the double indirect level, the sparse file (the hole reads as zeros), the empty file, the listing of `/ext` (a link has the type `SYMLINK`, a directory `DIRECTORY`, no dot entries) and of `many` (120 entries), the four kinds of links, the refusal of the loop, a missing file and a path through a file. The test requires `ext: device 3,`, `extclient: small says hello from ext2` and `extclient: ok`.
- Writing: host tests for the writable decision (clean state, error state, journal, unknown read-only feature), the inode link and block counts, the record encoder read back by the parser (with and without `filetype`), the block of a new directory and the bitmap helpers. End to end, the tree gets an empty `scratch/` directory and `extclient` runs the write check in it, with a 300000 byte file that reaches the double indirect level, plus names with spaces, capitals and 85 characters; `scripts/qemu_userland_test.sh` requires `e2fsck -fn` to pass on the partition and reads `scratch/keep.txt` back with `debugfs`.
- The manifest starts the same program a second time under the name `ext4probe` with `arg=4`, which is the ext4 volume. The test requires `ext: device 4: unsupported feature extents`.
